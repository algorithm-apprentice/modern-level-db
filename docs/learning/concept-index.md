# Concept-to-Code Index

Use this index when you know the storage-engine concept or behavior you want
to understand or change, but do not yet know which files matter. It narrows a
repository-wide search to a bounded reading set:

1. Read the linked learning lesson for the mental model.
2. Read the current reference or architecture document for the maintained
   contract.
3. Open the listed source entry points without following every helper.
4. Read the representative tests as executable examples.
5. Read the ADRs only when the rationale or rejected alternatives matter.

The source links identify stable responsibility boundaries, not every file
that can appear in a call graph. Update this index when a concept moves to a
different module, its primary test changes, or a later ADR changes the
responsibility boundary.

## Change routes

Use these routes to start common maintenance work without loading the whole
engine into memory.

| Intended change | Read first | Open next | Evidence that must remain |
|---|---|---|---|
| Change a persistent encoding | [Bytes and formats](02-bytes-and-formats.md) | The codec and its focused test under `tests/unit/format` or `tests/unit/table` | Golden bytes, malformed input, compatibility, and fuzz coverage |
| Change MemTable or SkipList behavior | [Memory and MVCC](03-memory-and-mvcc.md) | `memtable.*`, `skiplist.h`, then their unit tests | Snapshot visibility, unique internal keys, single-writer/concurrent-reader publication, arena accounting |
| Change WAL, rotation, or recovery | [WAL and recovery](04-wal-and-recovery.md) | `wal_format.*`, `wal_io.*`, `recovery.cc`, `database_write.cc` | WAL-before-visibility, crash-tail handling, checksums, sticky owner failure, crash/process tests |
| Change table layout or reading | [Tables, filters, and caches](05-tables-filters-and-caches.md) | `block*`, `table*`, filters/compression, then table tests | LevelDB bytes, corruption handling, compatibility, mapped/owned lifetime |
| Change point reads or iterators | [Reads and iterators](06-reads-and-iterators.md) | `lookup.cc`, `iterators.cc`, `db_iterator.cc`, then model/iterator tests | Snapshot result, deletion semantics, source order, output ownership, read-cost accounting |
| Change writes, flush, or compaction | [Writes and compaction](07-writes-and-compaction.md) | `write_path.*`, `database_write.cc`, `database_background.cc`, `flush.cc`, compaction files | WAL ordering, sequence publication, failure stickiness, retention rules, backpressure, performance gates |
| Change a platform or durability boundary | [WAL and recovery](04-wal-and-recovery.md), [platform reference](../reference/platform-support-and-durability.md) | `file_system.h` and the selected backend | Exact public guarantee, native error mapping, compatibility, crash/process tests on the affected platform |

For the procedure used to turn one of these routes into a reviewed change, see
[Document-first development](../development/document-first-development.md).
