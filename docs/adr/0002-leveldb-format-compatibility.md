# ADR-0002: Initial LevelDB Format Compatibility

- Status: Accepted
- Date: 2026-09-21

## Context

A new storage format would allow unconstrained design changes, but it would
remove the strongest available oracle for WAL, MANIFEST, SSTable, recovery, and
compaction behavior.

There is currently no deployed data requiring a migration framework.

## Decision

The initial implementation will read and write the original LevelDB WAL,
MANIFEST, internal-key, write-batch, and SSTable formats. “Original LevelDB
format” identifies the stable upstream format family; it does not imply that
Google publishes numbered v1/v2 format generations.

Compatibility is a development constraint and verification tool, not a promise
of permanent source, ABI, or bidirectional format compatibility.

No generic format-migration framework will be built before an accepted feature
requires an incompatible persistent representation.

## Consequences

- Golden files can be generated by either implementation and consumed by the
  other.
- Differential recovery and compaction tests are possible.
- Initial value kinds and table structures remain constrained by LevelDB.
- Features such as range tombstones require a later format-version ADR.
